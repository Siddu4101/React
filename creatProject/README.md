# ⚛️ React Project Setup & Fundamentals

## 📦 Creating a React project

### 1. Create React App

> **Note:** Create React App is a legacy option and is no longer recommended for new React projects. It is included here for comparison and for working with existing projects.

```bash
npx create-react-app app-by-create-react-app
cd app-by-create-react-app
npm start
```

Typical files and folders:

```text
public/
  index.html       # HTML page containing the root element
src/
  App.js           # Main application component
  index.js         # Creates the React root and renders App
package.json       # Project metadata, dependencies, and scripts
package-lock.json  # Locks the installed dependency versions
node_modules/      # Installed dependencies (generated by npm)
```

### 2. Create React with Vite

Vite provides a lightweight development server with fast startup and refresh times, making it a good choice for a new React project.

```bash
npm create vite@latest app-by-create-vite-latest
cd app-by-create-vite-latest
npm install
npm run dev
```

Choose **React** and a JavaScript or TypeScript variant when prompted.

Typical files and folders:

```text
index.html       # HTML page containing the root element
src/
  App.jsx        # Main application component
  main.jsx       # Creates the React root and renders App
package.json     # Project metadata, dependencies, and scripts
package-lock.json
node_modules/
```

### 3. Create a minimal project manually

The [`app-by-me/`](./app-by-me) folder contains a minimal React project created manually. Its main files follow the same general pattern as a Vite project:

```text
index.html
src/
  App.jsx
  main.jsx
package.json
```

## 🧭 How a React app starts

In these examples, `index.html` provides the page and a root DOM element. The entry file (`index.js` in Create React App or `main.jsx` in Vite) finds that element, creates a React root, and renders the `App` component inside it.

## 🔍 React Strict Mode

`<React.StrictMode>` enables additional development-only checks that help reveal unsafe or impure component behavior and deprecated APIs. In development, React may call a component's render logic more than once to help find these problems. This behavior does not affect production builds.

```jsx
// main.jsx
import React from 'react';
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = createRoot(document.getElementById('root'));

root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
```

For example, a local variable starts over whenever the component function runs:

```jsx
// App.jsx
export default function App() {
  let count = 0;
  count += 1;

  console.log('Local count:', count);

  return <h1>{count}</h1>;
}
```

With Strict Mode enabled, you may see `Local count: 1` logged more than once in development. Without Strict Mode, this additional development check is not performed. Avoid relying on render counts for application behavior.

## 📤 Exporting and importing components

### Default export

A module can have one default export. When importing it, you can choose the local name; curly braces are not used.

```jsx
// App.jsx
export default function App() {
  return <h1>Hello, world!</h1>;
}

// main.jsx
import MyApp from './App.jsx';
```

### Named exports

Named exports are imported by their exported name and written inside curly braces. You can use `as` if you want a different local name.

```jsx
// App.jsx
export function App() {
  return <h1>Hello, world!</h1>;
}

export function MyComponent() {
  return <p>My component</p>;
}

// main.jsx
import { App, MyComponent } from './App.jsx';
// Or rename an import:
import { App as MainApp } from './App.jsx';
```
